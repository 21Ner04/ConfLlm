# Docker: приложение с необязательными embeddings

## Два варианта запуска

Основной compose.yaml запускает приложение без локального embeddings-сервиса.
Дополнительный compose.rag.yaml добавляет CPU-сервис embeddings и chunking.

Серверы текстовой LLM, ASR и диаризации по-прежнему настраиваются отдельно.
Дополнительный файл не запускает их.

Создайте .env.docker из .env.docker.example и настройте внешние серверы
по основному README. Реальные ключи не публикуйте.

## Только приложение

Из корня проекта:

```bash
docker compose up --build -d
```

Локальный embeddings-сервис этой командой не создаётся.
Обычная обработка видео требует настроенных ASR, диаризации и текстовой LLM.
RAG-поиск требует доступного embeddings-сервиса, локального или внешнего.

Важно: эта команда не останавливает embeddings, если они уже были
запущены другим способом. Сначала остановите предыдущий RAG-запуск.

## Приложение с локальными embeddings

```bash
docker compose -f compose.yaml -f compose.rag.yaml up --build -d
```

При первом запуске сервис скачает модель:
sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2.

Веса сохраняются в Docker-томе confllm-rag-embedding-cache.
Приложение запускается после успешной проверки здоровья embeddings.
Первое скачивание может занять время.

Проверка:

```bash
docker compose -f compose.yaml -f compose.rag.yaml ps
docker compose -f compose.yaml -f compose.rag.yaml logs --tail=80 embeddings
```

Адреса embeddings и chunking задаёт дополнительный Compose-файл.
Для этого запуска они переопределяют значения из env_file.
Текстовая LLM продолжает использовать настройки .env.docker.

Порт embeddings не опубликован на хосте.
Из приложения сервис доступен по имени embeddings.
Основное приложение остаётся на http://localhost:8000/.

Использование другой embedding-модели требует отдельной проверки
совместимости и перестроения индекса.

## Остановка без удаления весов

Дождитесь окончания обработки и запросов:

```bash
docker compose -f compose.yaml -f compose.rag.yaml down
```

Контейнеры удаляются. Веса в именованном томе сохраняются.
Пользовательские data/, outputs/ и web_jobs/ не удаляются.

Embeddings настроены с restart: "no".
Они не должны автоматически запускаться только от открытия Docker Desktop.
Для запуска используйте явную Compose-команду.

Чтобы после остановки включить только приложение:

```bash
docker compose up -d
```

## Удаление скачанных весов

Сначала остановите RAG-запуск и удалите его контейнеры:

```bash
docker compose -f compose.yaml -f compose.rag.yaml down
docker volume rm confllm-rag-embedding-cache
```

Это удаляет кэш этой установки, включая скачанные веса.
Следующий запуск с compose.rag.yaml потребует повторного скачивания.

Не используйте down -v или массовую очистку Docker для этой задачи.

## Образ и исходники

Образ confllm-embeddings:local содержит Python и зависимости сервиса.
В текущем Dockerfile скачивание embedding-модели выполняется не при сборке,
а при запуске server.py. Веса сохраняются в HF_HOME внутри тома.

Для удаления также образа после остановки контейнеров:

```bash
docker image rm confllm-embeddings:local
```

После этого следующему запуску понадобится пересборка или получение образа.
Build cache Docker может оставаться; массовую очистку здесь не выполняем.

services/embeddings/ содержит исходники сервиса.
Его нужно оставить в репозитории.

## Ограничения

Docker на ноутбуке использует диск и ресурсы того же ноутбука.
Работающая модель занимает память; остановленная не выполняет вычисления,
но сохранённые веса и образ продолжают занимать диск.

Ограничение CPU сервиса — два ядра. Это не ограничение памяти
и не гарантия отсутствия влияния на работу ноутбука.

Новая Compose-конфигурация должна быть проверена запуском.
Проверки агента, выполненные ранее с отдельным контейнером,
не заменяют проверку этого способа развёртывания.
