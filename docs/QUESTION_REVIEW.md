# Проверка открытых вопросов: первая версия

Функция запускается вручную через API или через панель «Проверка открытых вопросов» в веб-редакторе.

## Требования

- Синхронизируемые результаты встреч с открытыми вопросами.
- Построенный RAG-индекс.
- Настроенные текстовая LLM, embeddings и разбиение текста.
- Текущий генератор `/api/rag/answer` должен работать.

## API

`POST /api/question-reviews/run`

Пример тела:

```json
{"limit": 1}
```

Можно выбрать конкретные вопросы:

```json
{"limit": 1, "question_ids": ["ID_ИЗ_API_ПАМЯТИ"]}
```

Допустимый limit: от 1 до 3. Обрабатываются только open_question
со статусом open или in_progress. Вопросы берутся из локальной памяти.

Запрос синхронный и может выполняться несколько минут из-за таймаутов
и повторной попытки существующего генератора. Для начала используйте limit=1.
Увеличивать таймауты и добавлять фоновую очередь следует отдельно.

Если вопросов больше limit, проверяется начало списка в стабильном порядке.
remaining не является курсором очереди: повтор без question_ids снова
проверит начало списка. Для остальных вопросов передавайте их ID явно.

`GET /api/question-reviews?limit=50`

Необязательный фильтр: question_id.
Возвращает сохранённую историю, включая предложения по уже закрытым
или изменённым вопросам. Это не список текущих открытых вопросов.

## Хранение и поведение

Предложения хранятся отдельно в data/question_reviews.sqlite3.
Исходная память, статусы вопросов и протоколы не изменяются.
Интерфейс принятия и отклонения предложений ещё не реализован.

Ответ генератора answered сохраняется как candidate_answer:
это кандидат для проверки человеком, а не подтверждённое решение.
no_sources и insufficient_sources сохраняются отдельно.
Ошибки возвращаются в errors и не сохраняются как отсутствие ответа.

Идентичные результаты не дублируются. Метрики и время не участвуют
в идентичности; при повторе сохраняется первая запись.
Изменение текста ответа или источников может создать новое предложение.

Поиск выполняется по всем проиндексированным встречам и только
по фрагментам расшифровок, согласно текущему генератору ответов.
Нет фильтра "только материалы после исходного вопроса".
Структурированные решения не являются отдельным источником генерации.

Нет интернета, фонового расписания, автоматического закрытия вопросов,
отдельного обнаружения противоречий и поиска подразумеваемых вопросов.
Проверка структуры цитат не доказывает фактическую корректность ответа.

Одновременно разрешён один запуск проверки в процессе приложения.
Это не распределённая блокировка: несколько Uvicorn workers и независимые
экземпляры приложения для этой версии использовать не следует.

Повторный запуск выполняет поиск и генерацию заново, даже если результат
впоследствии окажется дубликатом. Лимит ограничивает число вопросов,
но не является общим лимитом времени или токенов.

База содержит тексты вопросов и найденные фрагменты. Не публикуйте data/.
Тесты этого модуля используют подмену генератора и не проверяют
качество настоящей LLM или работоспособность всех API-маршрутов.

## Веб-интерфейс

1. Нажмите «Обновить вопросы».
2. Выберите открытый вопрос.
3. Нажмите «Проверить выбранный вопрос».
4. Проверьте предложение по приведённым цитатам.
5. Для сохранённых результатов используйте «Показать историю».

При пустом списке проверка отключена. История при этом доступна.
При выбранном вопросе история фильтруется по его ID.
Автоматическое принятие, закрытие и отклонение предложений не реализованы.

Прерывание ожидания в браузере не гарантирует остановку серверной проверки.
Перед повторным запуском проверьте историю.

5 ноября 2026 года:

- Автоматический набор: 42 passed in 11.18s.
- git diff --check завершился без замечаний.
- В веб-интерфейсе вручную проверены пустой список вопросов
  и пустая история.
- В отдельном Python-процессе внутри контейнера выполнен
  изолированный прогон с настоящими chunking, embeddings и текстовой LLM.
- Созданы две временные учебные встречи и отдельный индекс.
- На вопрос о дате получен кандидат ответа «20 ноября»
  с источником из второй встречи.
- На вопрос о неизвестном точном бюджете получен insufficient_sources.
- Оба исходных вопроса остались открытыми.
- Два результата сохранены в отдельной временной базе.
- Рабочие встречи, память и индекс не использовались.

Изолированный прогон вызывал обработчик API напрямую.
HTTP-маршруты отдельно проверены автоматическими тестами
с подменой генератора и синхронизации памяти.

Это smoke-проверка двух сценариев, а не репрезентативная оценка качества,
нагрузочный тест или подтверждение установки из чистого клона.
