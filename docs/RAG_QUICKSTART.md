# Вопросы по конференциям: запуск, проверка и ограничения

## Что реализовано

- Вопросы по открытой встрече или всем проиндексированным встречам.
- Семантический поиск по расшифровкам.
- Ответ текстовой LLM по найденным фрагментам.
- Ссылки на источники, реплики и таймкоды.
- Попытка отказа, если найденные материалы не дают основания для ответа.
- Отображение токенов, числа попыток и времени обработки запроса.
- Компактные раскрываемые карточки протокола.

Вопросы независимы: многотуровая история диалога не реализована.
Текущий endpoint ответов использует расшифровки, а не всю
структурированную память задач и решений.

Корректный JSON и существующий идентификатор источника не гарантируют
смысловую правильность ответа. Важные выводы следует проверять по цитате
и записи.

## Архитектура

1. Видео обрабатывается основным конвейером.
2. Текст разбивается токенизатором embedding-модели.
3. Фрагменты и векторы сохраняются в SQLite-индексе.
4. Вопрос преобразуется в вектор.
5. Поиск выбирает фрагменты.
6. Текстовая LLM возвращает утверждения с идентификаторами источников.
7. Backend проверяет идентификаторы и формирует ссылки.
8. Интерфейс показывает ответ, цитаты и метрики.

Embeddings не обучают текстовую LLM на материалах встреч.

## Что потребуется

- Docker с поддержкой Compose.
- Сервисы ASR и диаризации, совместимые с клиентами проекта.
- Текстовый OpenAI-совместимый API.
- CPU-сервис embeddings из `services/embeddings`.
- Интернет при первой сборке и скачивании embedding-модели.

Основной образ приложения не запускает серверы Parakeet, Nemotron
или текстовую LLM. Их нужно настроить отдельно.

Скопируйте `.env.docker.example` в `.env.docker`, если локального
файла ещё нет. Не перезаписывайте существующий файл без резервной копии.

Настройте PARAKEET_URL, NEMOTRON_URL, LLM_BASE_URL, LLM_API_KEY и LLM_MODEL.
Все адреса должны быть доступны из контейнера приложения.

В Docker `localhost` указывает на сам контейнер.
Для серверов на хосте в предлагаемой конфигурации предусмотрено
имя `host.docker.internal`.

## Запуск основного приложения

Из корня репозитория:

```bash
docker compose up -d --build app
docker compose ps
```

Интерфейс: http://localhost:8000/

API-документация: http://localhost:8000/docs

Если сборка из Windows/WSL идёт медленно, смотрите соответствующий
раздел основного README.

## Сборка CPU-сервиса embeddings

Из корня репозитория:

```bash
docker build -t confllm-embeddings:local services/embeddings
```

В текущем Dockerfile версии зависимостей не закреплены.
Это ограничение воспроизводимости: перед релизом следует зафиксировать
и повторно проверить набор версий.

## Первый запуск embeddings

Сначала запустите приложение. Затем, в Bash/WSL:

```bash
(
  set -eu

  CID="$(docker compose ps -q app)"
  test -n "$CID"

  NETWORK="$(docker inspect "$CID" \
    --format '{{range $name, $settings := .NetworkSettings.Networks}}{{println $name}}{{end}}' \
    | head -n 1)"
  test -n "$NETWORK"

  docker run -d \
    --name confllm-embeddings \
    --network "$NETWORK" \
    --restart=no \
    --cpus=2 \
    --memory=3g \
    -v confllm-embedding-cache:/cache \
    confllm-embeddings:local
)
```

Если контейнер с этим именем уже существует, не создавайте второй:
проверьте его настройки и используйте `docker start confllm-embeddings`.

Модель скачивается при первом запуске и хранится в Docker-томе.
GPU не используется: сервис явно настроен на CPU.
Первый запуск требует подключения к Hugging Face.

Посмотреть готовность:

```bash
docker logs -f --tail=60 confllm-embeddings
```

Дождитесь `Application startup complete`.
Ctrl+C завершает просмотр логов, не останавливая контейнер.

API embeddings не опубликован на порту хоста.
Сервис доступен контейнерам в подключённой Docker-сети.
Отдельной авторизации у этого тестового сервиса нет.

## Настройки RAG

В `.env.docker`:

```dotenv
LLM_EMBEDDING_BASE_URL=http://confllm-embeddings:8080/v1
LLM_EMBEDDING_API_KEY=local
LLM_EMBEDDING_MODEL=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
LLM_CHUNKING_URL=http://confllm-embeddings:8080/v1/chunks
```

После изменения переменных пересоздайте приложение:

```bash
docker compose up -d --no-build --force-recreate app
```

`/v1/chunks` — специальный endpoint данного проекта.
Обычный облачный embeddings API его, как правило, не реализует.
Токенизация фрагментов должна соответствовать используемой
embedding-модели.

## Построение индекса

Запускайте только одну переиндексацию одновременно.
Embeddings-сервис должен быть доступен.

```bash
docker compose exec -T app python -u - <<'PYCODE'
from pathlib import Path
from backend.rag_index import LocalVectorIndex

with LocalVectorIndex(Path("/app")) as index:
    print("Начинаю индексацию...", flush=True)
    count = index.reindex()
    print("Фрагментов:", count, flush=True)
PYCODE
```

В текущей конфигурации индексируются завершённые запуски
`completed` и `completed_needs_review`.
Запуски без читаемого итогового состояния пропускаются.

Также индексатор может читать документы из `knowledge/` и `docs/`.
Endpoint вопросов сейчас ищет только фрагменты типа `utterance`.

Обновление индекса не запускается автоматически после новой обработки
или сохранения редакции.

Замена embedding-модели требует перестроения индекса.
Очистка и запись векторной таблицы выполняются в одной транзакции.
Отдельная синхронизация базы памяти не входит в эту транзакцию.

В текущем Compose папки `knowledge/` и `docs/` не подключены как тома.
Для использования этих документов внутри Docker понадобится
дополнительная настройка копирования или томов.

## Работа в интерфейсе

- Для глобального поиска открывать встречу не нужно:
  выберите «Во всех проиндексированных встречах».
- Для поиска по конкретной встрече откройте её и выберите соответствующую
  область.
- Область встречи включает её проиндексированные запуски,
  а не обязательно только выбранный запуск.
- Цитаты доступны под ответом.
- Кнопка источника открывает нужный запуск и переводит видео к реплике.
- Воспроизведение запускается отдельно кнопкой Play.

Возможность перехода к видео зависит от наличия исходного файла и
корректного пути внутри контейнера. Старые абсолютные пути с другого
компьютера не переносимы автоматически.

## Метрики

Интерфейс показывает:

- входные токены текстовой LLM;
- выходные токены;
- сумму по полученным ответам, включая повторную попытку;
- количество попыток;
- время поиска, генерации и всего запроса на backend;
- имя модели и идентификатор запроса.

Если API не возвращает usage, показывается отсутствие данных.
Embeddings, индексация и предыдущая обработка видео в этот счётчик
токенов не входят. Это не расчёт денежной стоимости.

Метрики пока не являются постоянным журналом или системой мониторинга.
Время backend не равно полной задержке от браузера до отображения.

## Проверки перед демонстрацией

На используемой тестовой записи проверялись:

1. Вопрос о причине перехода спикера из логистики в AI:
   найден соответствующий источник и сформирован ответ.
2. Вопрос о точной зарплате, не указанной в найденных материалах:
   получен статус insufficient_sources.
3. Отображение токенов и времени ответа.
4. Запрос по всем встречам без предварительного открытия встречи.

Это отдельные ручные тесты, не гарантия качества на любых записях.

Повторите проверки на собственных материалах:
- вопрос с известным ответом;
- вопрос без ответа в источниках;
- переход к видео;
- вопрос по двум разным конференциям;
- сохранение и экспорт редакции.

## Локальные и облачные модели

Текстовая LLM может находиться на том же компьютере, на другом ПК
или у облачного провайдера.

Одной замены URL недостаточно для обещания полной совместимости.
Текущие вызовы используют Chat Completions, JSON-ответы и расширение
`chat_template_kwargs`. Конкретный сервер может не поддерживать
часть параметров.

Для другого провайдера нужно проверить параметры вызовов и провести
тесты. Это относится также к извлечению фактов, а не только к RAG.

Облачные ASR и диаризация должны соответствовать форматам запросов
клиентов проекта. Произвольные API не являются взаимозаменяемыми.

При использовании удалённых API соответствующие материалы покидают
компьютер: аудио — при удалённой обработке, найденный текст и вопрос —
при удалённом ответе LLM. Учитывайте права на записи и условия провайдера.

## Память и ограничения

В проекте есть backend-компоненты памяти задач и решений.
Полноценная пользовательская панель памяти и надёжное сопоставление
решений между конференциями пока не подтверждены ручными тестами.

Текущий RAG не означает:
- дообучение LLM;
- узнавание людей между встречами по голосу;
- автоматическое доказательство причин решения;
- гарантированное отсутствие галлюцинаций.

Имена говорящих могут быть предполагаемыми и требуют проверки.
Метки speaker_1 и speaker_2 локальны для записи.

## Остановка и повторный запуск embeddings

```bash
docker stop confllm-embeddings
docker start confllm-embeddings
docker stats confllm-embeddings
```

Контейнер создаётся отдельно от Compose.
`docker compose down` приложения его не останавливает.
Автоперезапуск отключён.

После удаления и создания Docker-сети проекта подключение
отдельного контейнера может потребовать восстановления.

## Полное удаление тестового сервиса

Только после завершения работы:

```bash
docker stop confllm-embeddings
docker rm confllm-embeddings
docker volume rm confllm-embedding-cache
docker image rm confllm-embeddings:local
```

Удаляются контейнер, кэш модели и образ.
Исходники в `services/embeddings` остаются в репозитории.

Без работающего embedding-сервиса новые вопросы векторному поиску
обрабатывать нельзя. Сохранённые видео, транскрипты и протоколы
не удаляются этими командами.

Не используйте массовую очистку Docker-томов для удаления одной модели.

## Перед публикацией

Не включайте:
- `.env` и `.env.docker`;
- API-ключи;
- личные записи;
- `outputs/`, `web_jobs/`, рабочие базы из `data/`;
- локальные модели и кэши.

Проверьте не только правила `.gitignore`, но и уже отслеживаемые файлы.
Не используйте `git add .` без просмотра изменений.

Тестовый пункт протокола и случайные пользовательские правки следует
удалять через редактор, если они не нужны для демонстрации.

## Проверка офлайн-тестов

В локальном окружении разработки выполнено:

```bash
.venv/bin/python -m pytest -q tests
git diff --check
```

Результат прогона 5 ноября 2026 года: **24 passed in 8.92s**.
Проверка Git diff завершилась без замечаний.

Набор включает проверки:
- поиска по фактам и рискам;
- приоритета сохранённой редакции протокола;
- сохранения идентификаторов источников;
- метрик на небольшом версионированном тестовом корпусе;
- исключения failed, running и запусков без корректного состояния;
- отката векторного индекса при ошибке embeddings.

Офлайн-тесты используют явные embedding_fn и chunking_fn.
Они не требуют работающих моделей и не заменяют интеграционные
проверки настоящей LLM, токенизатора, ASR и диаризации.

Рабочий режим без chunking_fn использует LLM_CHUNKING_URL.
