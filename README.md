# ConfLlm — транскрипция и черновик протокола встречи

ConfLlm превращает запись встречи в транскрипт с говорящими и черновик
протокола с обсуждениями, решениями, задачами и ссылками на источники.
Результат можно проверить и отредактировать в веб-интерфейсе,
а затем экспортировать в DOCX и PDF.

Проект предназначен для локального использования. Сгенерированный
протокол требует проверки человеком и не является утверждённым документом.

## Возможности

- Обработка записей через веб-интерфейс или CLI.
- Выделение интервалов речи с Silero VAD.
- Распознавание речи через отдельный сервер Parakeet.
- Диаризация: определение интервалов говорящих через Nemotron.
- Объединение текста, говорящих и временных отметок.
- Определение предполагаемых имён участников с сохранением оснований.
- Извлечение фактов с привязкой к исходным репликам.
- Веб-редактирование результатов.
- Экспорт черновика протокола в DOCX и PDF.
- Сохранение промежуточных результатов и состояния обработки.
- Запуск веб-приложения и инструментов обработки в Docker.

В проекте также сохранены альтернативные ASR-ветки GigaAM и Whisper.
Они не равнозначны основному сценарию запуска: для них нужны отдельные
зависимости, входные данные и настройки.

## Статус проверки

На одной реальной записи ранее подтверждён проход:
видео → аудио → VAD → Parakeet → Nemotron →
транскрипт со спикерами → извлечение фактов → JSON и Markdown.

Определение предполагаемых имён и экспорт DOCX/PDF проверялись отдельно
на сохранённом транскрипте.

Для Docker подтверждены:

- успешная сборка образа;
- запуск веб-приложения;
- статус контейнера `healthy`;
- ответ `200 OK` от `/api/health`;
- ручная проверка работы веб-интерфейса.

Эти проверки не означают, что полный AI-пайплайн с новой записью
проверен внутри контейнера или что чистая установка воспроизводима
на любой машине. Сквозная обработка зависит от внешних серверов моделей.

Результаты отдельных записей и тестовых фрагментов не являются
универсальной оценкой качества системы.

## Архитектура

```text
Запись встречи
      |
      v
FFmpeg: WAV, 16 kHz, mono
      |
      v
Silero VAD: интервалы речи
      |
      v
Подготовка фрагментов -> Parakeet: распознавание
      |
      +---------------- Nemotron: интервалы говорящих
      |
      v
Объединение текста, говорящих и таймкодов
      |
      v
LLM: предполагаемые имена и извлечение фактов
      |
      v
JSON / Markdown -> проверка и редактирование -> DOCX / PDF
```

| Компонент | Назначение | Где работает |
|---|---|---|
| FastAPI / Uvicorn | Веб-интерфейс и API | Приложение |
| FFmpeg | Извлечение и подготовка аудио | Приложение |
| Silero VAD / CPU PyTorch | Определение интервалов речи | Приложение |
| Parakeet | Распознавание речи | Отдельный HTTP-сервер |
| Nemotron | Диаризация | Отдельный HTTP-сервер |
| Qwen через OpenAI-совместимый API | Работа с именами и фактами | Отдельный LLM-сервер |
| python-docx / ReportLab | Экспорт документов | Приложение |

Docker-образ включает приложение, FFmpeg, curl, CPU-зависимости VAD
и инструменты экспорта. Он не запускает серверы Parakeet, Nemotron и LLM.

## Быстрый старт через Docker

Команды ниже выполняются из корня проекта в Linux или WSL.
Нужны Docker с поддержкой Compose и доступ к серверам моделей
для полного цикла обработки.

### 1. Подготовьте конфигурацию

Создайте локальный файл настроек, не перезаписывая существующий:

```bash
if [ ! -e .env.docker ]; then
  cp .env.docker.example .env.docker
fi
```

Отредактируйте `.env.docker`:

| Переменная | Назначение |
|---|---|
| `PARAKEET_URL` | Адрес сервера распознавания |
| `NEMOTRON_URL` | Адрес сервера диаризации |
| `LLM_BASE_URL` | Базовый URL OpenAI-совместимого API |
| `LLM_API_KEY` | Ключ доступа к LLM |
| `LLM_MODEL` | Идентификатор обслуживаемой модели |

Сохраняйте путь API в `LLM_BASE_URL`, который требуется вашему серверу.

Внутри контейнера `localhost` указывает на сам контейнер.
Для серверов на хосте Docker Desktop используйте
`host.docker.internal` с фактическим портом и путём API.
Для серверов на другой машине используйте доступный сетевой адрес.

Для Docker Engine на Linux доступ к сервисам хоста может требовать
дополнительной настройки сети. Не считайте адрес
`host.docker.internal` автоматически доступным во всех окружениях.

Не добавляйте `.env.docker` и реальные ключи в Git.

### 2. Подготовьте каталоги и соберите образ

Перед переключением с локального запуска дождитесь завершения
текущей обработки. Убедитесь, что порт 8000 свободен.

```bash
mkdir -p data outputs web_jobs

export LOCAL_UID="$(id -u)"
export LOCAL_GID="$(id -g)"

docker compose build
docker compose up -d --no-build
```

Каталоги с данными должны быть доступны на запись пользователю контейнера.
Не используйте `chmod 777` как универсальное решение проблем с правами.

### 3. Проверьте запуск

```bash
docker compose ps
docker compose logs --tail=100 app
curl --fail http://localhost:8000/api/health
```

Откройте:

- приложение: http://localhost:8000/
- документацию API: http://localhost:8000/docs

Compose публикует порт на `127.0.0.1`: приложение рассчитано
на локальный доступ, а не на открытый интернет.

Healthcheck проверяет доступность API, но не готовность серверов моделей
и не успешность полного цикла обработки.

Дополнительные проверки внутри контейнера:

```bash
docker compose exec app python -m pip check

docker compose exec app python -c \
  "from silero_vad import load_silero_vad; load_silero_vad(); print('VAD OK')"
```

### Примечание для Windows / WSL

При локальной проверке сборка из `/mnt/c/...` очень долго оставалась
на этапе `load build context`. Из небольшого контекста в файловой
системе WSL передача завершилась за доли секунды.

Если возникает похожая проблема:

- проверьте `.dockerignore` и размер контекста;
- не включайте видео, модели, `.venv` и результаты обработки в образ;
- используйте рабочий checkout внутри файловой системы WSL,
  например `~/projects/ConfLlm`, вместо каталога `/mnt/c/...`.

Временные папки сборки конкретного разработчика не являются частью
проекта и не нужны для обычного запуска.

### Данные контейнера

| Каталог хоста | Каталог контейнера | Содержимое |
|---|---|---|
| `data/` | `/app/data` | Рабочие аудиофайлы и фрагменты |
| `outputs/` | `/app/outputs` | Результаты обработки и редакции |
| `web_jobs/` | `/app/web_jobs` | Загрузки, состояния заданий и журналы |

Не удаляйте эти каталоги при обновлении образа.
Они могут содержать конфиденциальные данные.

Старые результаты могут включать абсолютные пути локального окружения.
Их переносимость между локальным запуском и контейнером не гарантируется.
Для сквозной проверки Docker используйте новую обработку записи.

### Остановка и обновление

Сначала дождитесь завершения обработки.

Остановка:

```bash
docker compose down
```

После изменения кода:

```bash
export LOCAL_UID="$(id -u)"
export LOCAL_GID="$(id -g)"

docker compose build
docker compose up -d --no-build
```

Не выполняйте запуск после неуспешной сборки в расчёте на новый образ.
Перезапуск может прервать worker и дочерние процессы.
Автоматическое продолжение всего пайплайна после сбоя не реализовано.

## Локальная разработка

Основное окружение проекта — Python 3.12, Linux / Ubuntu / WSL.

FFmpeg и curl устанавливаются отдельно. Например, в Ubuntu:

```bash
sudo apt-get update
sudo apt-get install -y \
  python3-venv ffmpeg curl fonts-dejavu-core libgomp1 libsndfile1
```

Создание Python-окружения:

```bash
python3 -m venv .venv
source .venv/bin/activate

python -m pip install \
  -r requirements-torch.txt \
  --index-url [https://download.pytorch.org/whl/cpu](https://download.pytorch.org/whl/cpu)

python -m pip install \
  -r requirements.txt \
  -r requirements-export.txt \
  -r web_requirements.txt \
  -r requirements-vad.txt \
  -c requirements-torch.txt

python -m pip check
```

Этот набор соответствует основной схеме зависимостей Dockerfile.
Зависимости альтернативной ветки GigaAM требуют отдельной подготовки.
Наличие одного `requirements.txt` не означает наличие всего окружения.

Подготовьте `.env`, не перезаписывая существующий:

```bash
if [ ! -e .env ]; then
  cp .env.example .env
fi
```

Заполните настройки LLM и адреса серверов.
Для CLI адреса Parakeet и Nemotron можно передать явно.

Запуск веб-приложения:

```bash
python -m uvicorn backend.main:app --reload --port 8000
```

Не запускайте локальное приложение и контейнер одновременно
над одними и теми же рабочими данными.

## Единый CLI-пайплайн

После подготовки окружения, конфигурации и серверов моделей:

```bash
python run_pipeline.py \
  --video data/meetings/meeting_001/source/video.mp4 \
  --meeting-id meeting_001 \
  --parakeet-url http://АДРЕС_ПК:8083 \
  --nemotron-url http://АДРЕС_ПК:8090
```

Замените путь к видео и адреса серверов своими значениями.

Каждый запуск создаёт отдельные каталоги:

```text
data/meetings/{meeting_id}/runs/{run_id}/
outputs/{meeting_id}/{run_id}/
```

Идентификатор встречи допускает латинские буквы, цифры,
подчёркивания и дефисы; длина — от 1 до 80 символов.

Среди результатов обработки:

- интервалы речи и результаты распознавания;
- объединённый транскрипт в JSON и TXT;
- предполагаемые имена участников;
- факты в JSON и Markdown;
- документы DOCX и PDF;
- состояние этапов обработки.

Автоматическое продолжение всего запуска после сбоя пока не реализовано.
Перед повторным использованием сохранённых промежуточных результатов
проверяйте соответствие исходной записи и настроек.

## Источники, предполагаемые имена и проверка результата

Экстрактор получает от LLM идентификаторы исходных реплик.
Оригинальные тексты, говорящие и таймкоды добавляются программно.
Ошибки структуры и ссылок вызывают ограниченные повторные попытки.
Неполный результат явно помечается и возвращает ненулевой код завершения.

Имена участников являются предположениями, а не подтверждённой
идентификацией личности. Для них сохраняются основания и статусы.
Неизвестные имена могут оставаться `unresolved`,
противоречащие кандидаты — `conflict`.

Исходные идентификаторы говорящих сохраняются в транскрипте и источниках.
В проекте предусмотрена резервная логика для имён; её наличие
не гарантирует продолжение при любой ошибке этапа.

Наличие цитаты не доказывает правильность пересказа.
Перед использованием документа проверьте:

- соответствие фактов исходным репликам;
- решения и поручения;
- исполнителей и сроки;
- имена участников;
- отсутствие повторов и потерянного контекста.

Таймкоды источников относятся к репликам, а не обязательно
к точным границам процитированного фрагмента.

## Тесты и учебные проверки

Тесты резервной логики имён:

```bash
python -m unittest discover \
  -s tests \
  -p 'test_speaker_names_fallback.py' \
  -v
```

Они используют локальные тестовые данные и не требуют серверов моделей.

Отдельная учебная проверка LLM при настроенном и доступном сервере:

```bash
python check_llm.py
python check_protocol_example.py
python export_protocol_example_markdown.py
```

Учебный пример сравнивает шесть полей с ожидаемыми значениями.
Это не оценка качества на всех реальных встречах.

## Альтернативные ASR-ветки

Parakeet — ветка единого CLI-пайплайна.

GigaAM и Whisper сохранены для экспериментов и сравнения.
Перед отдельным запуском проверяйте параметры и пути конкретного скрипта:
часть вспомогательных сценариев ориентирована на `meeting_001`.

- GigaAM требует отдельной установки `gigaam` и совместимого окружения.
- Whisper использует результаты отдельно запущенного распознавания.
- Отдельный запуск `extract_meeting_facts.py` не следует считать
  автоматически настроенным на произвольную ASR-ветку.
- Результаты сравнения находятся в `benchmarks/`.
- Метрики коротких фрагментов не характеризуют качество всей записи.

## Демонстрация

### Без полного AI-прохода

1. Запустите приложение.
2. Проверьте `/api/health`.
3. Если есть совместимые и разрешённые к показу результаты,
   откройте их в веб-интерфейсе.
4. Покажите проверку фактов, редактирование и экспорт документов.

Готовые пользовательские результаты не поставляются автоматически
вместе с Docker-образом. Перенос старых результатов может потребовать
проверки сохранённых путей.

### Полная обработка

1. Запустите Parakeet, Nemotron и LLM.
2. Настройте доступ к ним из приложения.
3. Загрузите новую запись без конфиденциальных данных.
4. Дождитесь завершения обработки.
5. Проверьте факты и предполагаемые имена.
6. Экспортируйте DOCX и PDF.

До публикации примеров и скриншотов проверьте права на материалы
и отсутствие персональных данных.

## Ограничения и безопасность

- Приложение рассчитано на локальное использование и не имеет авторизации.
- Не публикуйте API приложения и серверы моделей в интернете без защиты.
- Одновременно поддерживается одна веб-обработка.
- В веб-загрузке предусмотрен лимит 1 GiB.
- Веб-интерфейс принимает видео MP4, MKV, MOV, WEBM, AVI и M4V.
  Внутренний WAV не означает поддержку отдельной загрузки аудио через UI.
- Полная запись и все извлечённые факты требуют ручной проверки.
- Обработка блоками может терять контекст и создавать повторы.
- Предполагаемые имена могут быть неверными или не определиться.
- Автоматическое продолжение всего пайплайна после сбоя не реализовано.
- Для PDF нужен шрифт с поддержкой кириллицы;
  Dockerfile устанавливает DejaVu.
- Основные зависимости закреплены, но полного транзитивного lock-файла нет.
- Доступность CPU-пакетов зависит от версии Python и индекса PyTorch.
- Лицензии моделей, библиотек и права на входные материалы
  проверяются отдельно.
