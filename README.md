# ConfLlm — транскрипция и черновик протокола встречи

## Единый запуск пайплайна

Полный проход на одной записи подтверждён: видео → WAV → Silero VAD →
VAD-фрагменты → Parakeet → Nemotron → транскрипт со спикерами →
извлечение фактов → JSON и Markdown.

Серверы Parakeet, Nemotron и Qwen запускаются отдельно.
Адреса Parakeet и Nemotron передаются параметрами, настройки Qwen —
через `.env`.

```bash
./.venv/bin/python run_pipeline.py \
  --video data/meetings/meeting_001/source/video.mp4 \
  --meeting-id meeting_001 \
  --parakeet-url http://АДРЕС_ПК:8083 \
  --nemotron-url http://АДРЕС_ПК:8090
```

Каждый запуск создаёт новые папки с идентификатором времени.
Автоматическое продолжение всего пайплайна после сбоя пока не реализовано.

Экстрактор получает от LLM идентификаторы реплик-источников.
Оригинальные тексты, спикеры и таймкоды добавляются программно.
Ошибки структуры и ссылок вызывают ограниченные повторные попытки.
Неполный результат явно помечается и возвращает ненулевой код завершения.

Итог остаётся черновиком: наличие источника не гарантирует правильность
пересказа. Имена участников пока автоматически не определяются.
DOCX и PDF пока не подключены.

Зависимости ASR-окружения ещё необходимо полностью зафиксировать:
одного текущего `requirements.txt` недостаточно для воспроизведения
всех этапов в чистом окружении.


Проект обработки записей встреч и интервью:
видео → аудио → распознавание речи → сопоставление с говорящими →
извлечение фактов с цитатами → JSON и Markdown.

## Статус

На одной реальной записи получены транскрипты и черновик извлечения
фактов: 16 пунктов обсуждения. Решения и поручения автоматически
не извлечены. Это результат конкретной записи, а не доказательство
отсутствия ошибок или универсального качества системы.

Результат имеет статус `draft_needs_review`. Он не является утверждённым
протоколом. При подготовке текущего результата вручную исправлялись
смешение источников и изменённая моделью цитата; изменения сохранены
в локальных журналах.

Общий merge-скрипт проверен на сохранённых результатах GigaAM и Parakeet:
JSON и TXT совпали с результатами прежних отдельных скриптов.

## Компоненты

| Этап | Компонент |
|---|---|
| Извлечение аудио | FFmpeg |
| Определение участков речи | Silero VAD, CPU |
| Распознавание | Whisper через whisper.cpp; GigaAM; Parakeet через HTTP |
| Разделение говорящих | Nemotron 3 Diarization через NeMo-Speech.cpp |
| Сопоставление текста и говорящих | Python, пересечение временных интервалов |
| Извлечение фактов | Qwen через OpenAI-совместимый API llama.cpp |
| Результат | JSON и Markdown с источниками |

Whisper, GigaAM и Parakeet — альтернативные ветки распознавания.
Silero определяет интервалы речи, Nemotron — интервалы говорящих.
Имена людей автоматически не определяются.

## Скрипты

| Файл | Назначение |
|---|---|
| `detect_speech_silero.py` | Интервалы речи в исходном WAV |
| `prepare_asr_chunks.py` | Подготовка фрагментов по VAD с исходными смещениями |
| `transcribe_gigaam_chunks.py` | GigaAM `multilingual_ctc`, CPU, таймкоды слов |
| `transcribe_parakeet_chunks.py` | Parakeet через HTTP, таймкоды слов |
| `merge_asr_transcript.py` | Объединение нормализованных результатов GigaAM или Parakeet с Nemotron и VAD |
| `merge_whisper_transcript.py` | Объединение результата Whisper с Nemotron и VAD |
| `export_whisper_transcript.py` | TXT из Whisper JSON без говорящих |
| `extract_meeting_facts.py` | Извлечение фактов из объединённого транскрипта GigaAM; JSON и Markdown |
| `check_llm.py` | Проверка подключения к LLM |
| `check_protocol_example.py` | LLM-проверка на учебном тексте с ожидаемыми ответами |
| `export_protocol_example_markdown.py` | Markdown для учебного примера |

## Структура данных

- `examples/meeting_001.txt` — учебный текст для проверки извлечения.
- `benchmarks/` — эталоны, результаты и описание сравнения ASR.
- `data/` — локальные видео, аудио, диаризация и объединённые транскрипты.
- `outputs/` — локальные результаты распознавания и извлечения фактов.
- `.env.example` — шаблон конфигурации без секретов.

`data/`, `outputs/`, `.env`, модели и резервные копии исключены из новых
коммитов. Если материалы ранее коммитились, исключение не удаляет их
из истории Git.

## Окружение

Команды выполняются из корня проекта в Ubuntu/WSL. Используемый Python:
3.12.3.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

`requirements.txt` пока не описывает полное ASR-окружение.
Для Silero нужны дополнительные зависимости `torch` и `silero-vad`.
GigaAM импортирует `gigaam` и `torch`; в текущем окружении ConfLlm
эти зависимости отсутствуют. Установку и версии GigaAM ещё требуется
зафиксировать и проверить в чистом окружении.

FFmpeg и curl устанавливаются отдельно. Серверы моделей запускаются
вне Python-скриптов проекта; единой команды запуска всего конвейера пока нет.

## Конфигурация

Если `.env` отсутствует, скопируйте `.env.example` в `.env` и задайте
адрес llama.cpp, API-ключ и идентификатор обслуживаемой модели.
Не перезаписывайте существующий `.env` без сохранения настроек.

Для Parakeet текущий скрипт читает переменную окружения терминала:

```bash
export PARAKEET_URL="http://АДРЕС_ПК:8083"
```

Parakeet использует модель `parakeet-tdt-0.6b-v3.oss-align.q8_0`.
Сервер должен быть запущен отдельно.

HTTP-серверы без настроенной защиты не следует публиковать в интернете.

## Основной сценарий GigaAM

Пути привязаны к `meeting_001`. Перед запуском проверьте настройки
в коде и наличие входных файлов.

### Аудио

```bash
mkdir -p data/meetings/meeting_001/audio outputs
ffmpeg -i data/meetings/meeting_001/source/video.mp4 \
  -map 0:a:0 -vn -ac 1 -ar 16000 -c:a pcm_s16le \
  data/meetings/meeting_001/audio/audio.wav
```

### VAD и распознавание

После подготовки необходимых зависимостей:

```bash
python detect_speech_silero.py
python prepare_asr_chunks.py
python transcribe_gigaam_chunks.py
```

Для объединения также нужен заранее полученный результат диаризации:

```text
data/meetings/meeting_001/diarization/nemotron_response.json
```

### Объединение

```bash
python merge_asr_transcript.py --backend gigaam
```

Результат:

```text
data/meetings/meeting_001/transcript_gigaam_vad_v1/aligned_transcript.json
data/meetings/meeting_001/transcript_gigaam_vad_v1/aligned_transcript.txt
```

Существующая выходная папка не перезаписывается. Для отдельной проверки
используйте `--out` с новым путём.

### Извлечение фактов

При настроенном и запущенном сервере llama.cpp:

```bash
python extract_meeting_facts.py
```

Результат текущей конфигурации:

```text
outputs/meeting_001_facts_gigaam_v2/facts.json
outputs/meeting_001_facts_gigaam_v2/facts.md
```

Сохранённые блоки могут использоваться повторно. Перед изменением
источника или настроек нужно проверить механизм кеширования.
Номера в локальных путях обозначают существующие экспериментальные
артефакты; действующий скрипт извлечения один.

## Альтернативные ASR-ветки

Parakeet после подготовки VAD-фрагментов и запуска сервера:

```bash
python transcribe_parakeet_chunks.py
python merge_asr_transcript.py --backend parakeet
```

Whisper использует отдельно полученный JSON:

```text
outputs/meeting_001_transcript_v2.json
```

```bash
python merge_whisper_transcript.py
python export_whisper_transcript.py
```

Текущий экстрактор фактов по умолчанию подключён к GigaAM-транскрипту,
а не автоматически ко всем ASR-веткам.

## Учебная проверка LLM

При доступном сервере llama.cpp:

```bash
python check_llm.py
python check_protocol_example.py
python export_protocol_example_markdown.py
```

Проверка сравнивает шесть полей с ожидаемыми значениями. Это отдельный
учебный пример, а не оценка качества на всех реальных встречах.

## Ограничения

- Полная запись и все извлечённые факты ещё не проверены вручную.
- Говорящие представлены идентификаторами, а не подтверждёнными именами.
- Наличие цитаты не доказывает правильность пересказа.
- Таймкоды источников относятся к репликам, не к точным границам цитаты.
- Обработка блоками может терять контекст и создавать повторы.
- Метрики на отдельных тестовых фрагментах не характеризуют всю запись.
- Подготовка чистого воспроизводимого окружения ещё не завершена.

## Следующие шаги

- Зафиксировать установку всех ASR-зависимостей и серверов моделей.
- Проверить все 16 пунктов текущего результата по источникам.
- Проверить основную схему извлечения на примере с решениями и поручениями.
- Добавить параметры входов и выходов вместо жёстко заданных путей.
- Добавить автоматические тесты без обязательного запуска моделей.
- Подготовить разрешённый к публикации демонстрационный результат.

## Экспорт протокола и предполагаемые имена

Зависимости экспорта:

```bash
python -m pip install -r requirements-export.txt
```

В единый пайплайн добавлены:
- определение предполагаемых имён по транскрипту;
- сохранение speaker_names.json с основаниями и статусами;
- экспорт черновика протокола в DOCX и PDF;
- отображение предполагаемых имён в документах без замены
  исходных идентификаторов в транскрипте и источниках.

Имена определяются окнами с перекрытием. Неизвестные имена
остаются unresolved, противоречащие кандидаты — conflict.
Все найденные имена требуют проверки.

Отдельное определение имён и экспорт с именами проверены
на сохранённом транскрипте meeting_001.
Полный десятиэтапный запуск после интеграции ещё не проверен.

JSON фактов и Markdown пока сохраняют исходные идентификаторы.
Ошибка этапа определения имён останавливает пайплайн.
Для PDF необходим доступный TTF-шрифт с поддержкой кириллицы.

## Запуск приложения через Docker

Контейнер включает веб-приложение, FFmpeg, CPU Silero VAD и экспорт
DOCX/PDF. Серверы Parakeet, Nemotron и LLM запускаются отдельно.

### Настройки

Создайте `.env.docker` на основе `.env.docker.example` и укажите:
`PARAKEET_URL`, `NEMOTRON_URL`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`.

Не добавляйте `.env.docker` в Git. Он не включается в образ.
Конфигурация передаётся через Compose `env_file`.

Внутри контейнера `localhost` относится к самому контейнеру.
Для серверов на хосте Docker Desktop используйте
`host.docker.internal`, сохраняя реальные порты и путь API.
Для серверов на другой машине используйте доступный сетевой адрес.

### Сборка и запуск из WSL/Linux

Перед первым запуском убедитесь, что на порту 8000 не работает
локальный экземпляр Uvicorn. Не останавливайте обработку ради переключения:
сначала дождитесь её завершения.

```bash
export LOCAL_UID="$(id -u)"
export LOCAL_GID="$(id -g)"

docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=100 app
```

Откройте http://localhost:8000/.
API: http://localhost:8000/docs.

### Проверка

```bash
docker compose exec app python -m pip check
docker compose exec app python -c "from silero_vad import load_silero_vad; load_silero_vad(); print('VAD OK')"
```

Проверка `/api/health` подтверждает доступность API, но не серверов моделей.
После сборки отдельно проверьте полный проход с новой загрузкой видео.

### Данные

Папки хоста подключены в контейнер:
- `data` → `/app/data`: рабочие аудиофайлы и фрагменты;
- `outputs` → `/app/outputs`: результаты обработки и редакции;
- `web_jobs` → `/app/web_jobs`: загрузки, состояния заданий и журналы.

Не удаляйте эти папки для обновления образа.

Старые результаты могут содержать абсолютные пути WSL.
Их переносимость между локальным запуском и контейнером пока не гарантируется.
Для проверки Docker создайте новый запуск через веб-интерфейс.

### Остановка и обновление

Сначала дождитесь завершения обработки, затем:

```bash
docker compose down
```

После изменения кода:

```bash
docker compose up -d --build
```

Перезапуск контейнера не равнозначен перезапуску одного API:
он может остановить worker и дочерние процессы. Автоматическое продолжение
прерванных этапов не реализовано.

### Ограничения

- Локальное использование, без авторизации.
- Одна веб-обработка одновременно.
- Не запускайте одновременно локальный API и контейнер над одними данными.
- Версии основных библиотек закреплены; полного транзитивного lock-файла
  и фиксации базового образа по digest пока нет.
- CPU-версии PyTorch и TorchAudio должны существовать в индексе PyTorch
  для выбранной версии Python.
- Docker-сборка считается проверенной только после успешной сборки
  и контрольной обработки записи.
